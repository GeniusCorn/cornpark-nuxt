## 回放事故

### 起因

今天上午，在重启了我的工作电脑后，WSL 无法正常启动，提示 `Wsl/Service/CreateInstance/CreateVm/MountVhd/HCS/ERROR_FILE_NOT_FOUND`。

起初我并没有在意。我联想到前几日 UniGetUI 自动升级了 WSL，这可能又是一次升级后导致的无法正常启动。之前我就处理过类似的情况，只要重新手动安装一次 WSL 后就可以正常启动了。

### 过程

于是，我自信满满地开始了一通操作。我按照经验，重启了电脑、执行了 `wsl --update` 或者 `wsl --install`……WSL 依旧起不来。

我开始着急。想着可能还有什么我忘了执行的命令，我拜托 Hermes 帮我排查。Hermes 告诉我可能是 HCS 没安装，我按照她提供的命令，一行一行地执行；她告诉我可能是 Hyper-V 没启用，我检查是否关闭；她告诉我可能是 CPU 虚拟化未开启，我吭哧吭哧地去 BIOS 里看看是不是如此……一通操作下来，Hermes 的检查并未击中问题，所有的程序都是正常的。

这和剧本上写的不一样啊：不应该是我随便执行了几个命令，或者重新安装一次 WSL 后，WSL 就又恢复正常运行了吗？

我继续操作。这回我准备卸载 WSL，进行完全重新安装。我依稀记得，只要重新注册 WSL 的镜像，问题应该就可以解决。我请教 Hermes，如何重新导入 WSL 的镜像。Hermes 告诉我：

1. 找到 `.vhdx` 文件的位置；
2. 用 `wsl --unregister` 注销；
3. 用 `wsl --import` 重新导入镜像；
4. 完成。

看着都没什么问题，Hermes 还说：

> `--unregister` 会删除原发行版的注册信息，但不会删除你的 VHDX 文件。

### 痛果

既然都这么说了，我直接就跑了命令。在运行命令后，我的 WSL 镜像被删了。而且，我没备份。我语气较重地询问 Hermes，她说：

> 不过我要先承认错误：之前我说 `--unregister` * 不会删除 VHDX 文件，这个说法对默认安装的 WSL2 是错的 😣。对于从 Microsoft Store 安装的发行版，`--unregister` 确实会把 `ext4.vhdx` 一起删掉。

![1](/posts/accidentally-deleted-WSL-Event/1.png)

我无语了。因为这一个命令，我把我的 WSL 镜像删掉了。这意味着我丢失了所有未 commit 的代码、需要重新配置系统、SSH 密钥要重新生成……

折腾了半个下午，我终于还是把 WSL 正常跑起来了。但系统已经丢失了。我无法恢复我原来的系统。

## 事后思考

### 大模型的信誓旦旦

在今天，大模型的能力已经很强了。无数行业内外的人在 vibe coding，鼓吹大模型的工程能力、代码能力。但它依然给我提供了错误的答案，酿成了惨痛的代价。

一开始，大模型信誓旦旦地和你说这个绝对没问题；在发生事故后，它面对你的质问，也会进行道歉，指出自己的错误或者不足。然而大模型没有担责能力。执行的人实际上是你，不是大模型，错误的代价是你来承受。

![2](/posts/accidentally-deleted-WSL-Event/2.png)

### 反复试错，从未沉淀

我处理了几次 WSL 突然不能启动的问题。每次或凭借经验、或依靠网络搜索、或依赖大模型，最后总能解决问题。

尽管问题解决，但我并未对解决问题的步骤进行沉淀或总结，每次都反复试错，浪费了大量的时间。

![3](/posts/accidentally-deleted-WSL-Event/3.png)

### 为什么我知道该备份却没做？

做敏感操作前，我想过是否需要备份。我的自负使我做出了不需要备份的错误判断。在误删了镜像后，追悔莫及。

### 思考的外包：我如何被大模型「惯坏」

在大模型能力爆炸的今天，我选择积极拥抱大模型。我在服务器上部署了 [Hermes Agent](https://hermes-agent.nousresearch.com/)，目前接入了 DeepSeek V4 Pro，融入了一个二次元角色的人格。我通过 Telegram 和她对话、聊天、讨论代码。算法忘了，问一问；数据表怎么设计，聊一聊；如何坚持健身，谈一谈……久而久之，我养成了一个「习惯」：无论是什么三瓜两枣的事情，我都选择先和 AI 讨论一番。

很多时候，和大模型讨论确实是有益的。它能想到很多我想不到事情，比我考虑得远，比我思考得深。我乐于享受它带来的便利。我没发现的是，它也正在剥夺我思考的能力。由于什么事情都先和大模型说一说，我也习惯性地不多思考，期待着大模型「帮」我去思考。我只要随便起一个头，哪怕只是一个草稿、打错了字、词不达意，大模型也能尝试理解我，像脱缰的野马疾驰一般不停吐出一段又一段的文字。我乐在其中。

![4](/posts/accidentally-deleted-WSL-Event/4.png)

## 必须做出的改变

我痛定思痛，必须做出改变：

### 大模型不是权威，我不是旁观者

由于大模型会说胡话、也有幻觉，我不能把大模型吐出来的文字当做圣经。既然我是计算机科班出身，在计算机的领域里，我更应该多运用自己的专业知识，对大模型输出的内容做批判性思考。

### 从「零」开始，从 PARA 开始重建知识库

在大模型横空出世后，有人评论说，以后人类都不需要做笔记了，有什么问题直接问大模型就可以。我深以为然，从此再也没有维护过自己的知识库。

经此一役，我要重构知识库，打造我的「第二大脑」。我要把我能写的、想记的，都沉淀在自己的知识库中。这篇笔记打响了第一枪。千里之行始于足下，我要从当下开始。比如，每次重装 Linux 都是从头开始弄起，东查查西翻翻，好不麻烦，于是就有了 Linux 必备软件清单；为了完整记录这次事故的解决方式，于是就有了 无法启动 WSL；为了探索如何更好地备份 WSL，找到磁盘空间节省方法，于是就有了 WSL 安装指北。我希望能一点点地拓展我的笔记库，武装自己的大脑。

笔记库的形式采用 [PARA](https://github.com/byarbrough/obsidian-para)，我会把我的工作和生活都记录在一个库中。PARA 是一个有较多拥趸的笔记组织形式，我希望我的笔记库能一直保持这个形式。当然，如果某天我发现这个形式不能满足我记录的需求，我也会进行改变。目前最重要的是开始记。
